# Neko interface memory

Status: initial Android design system implemented. Use these values as the working baseline and revise only as the first APK and screen previews are reviewed.

## User-provided visual authority

- `image.png`: rounded illustrated lucky cats, strong outlines, expressive faces, raised paws, collar and bell. Neko's first model blends a white lucky-cat body with orange tabby ears and markings, cyan-accented round glasses, and a bell. This practical first art direction remains open to review.
- `image copy.png`: main interface inspiration with charcoal surfaces, cyan accents, rounded cards, pill controls, clear headings, and compact navigation.
- `image copy 2.png`: secondary-screen inspiration with prominent metrics, progress rings, spacious composition, and selective cyan/mint gradients.
- `image copy 3.png`: light-theme and conversation inspiration with soft backgrounds, white cards, pastel glow, and a comfortable composer.

Both dark and light modes are requested. Keep layouts and component roles consistent across modes. Preserve readable finance tables and honest transaction statuses. The references' promotional text, voice controls, and model selectors do not independently establish Neko features.

- The main destination is Neko's conversation with a message composer. Keep spending dashboards off that screen. Ledger, insights, schedules/activity, settings, and groups remain separate destinations.
- The browser preview uses `preview/neko-mascot.png`: a transparent, softly shaded 3D-style still based on `image.png`. Do not use an interactive model viewer or drag/rotate controls in the preview. Give Neko a restrained speaking bounce while the comic-style reply bubble appears, and honor both the preview's Reduce motion control and the OS preference.
- Native Android still uses `app/src/main/assets/models/neko.glb`, generated by `tools/build_neko_mascot.py` and rendered with SceneView/Filament. The browser preview does not load that model.

## Native Android requirements

- Use dp for spacing and sizes, sp for text, and native system/keyboard insets.
- Plan interactive targets of at least 48dp by 48dp, independent of the visible icon size.
- Support font scaling, TalkBack labels, readable contrast, and reduced motion.
- Keep the cat animation subtle and tied to meaningful states. Its presence must not obstruct transaction review or ledger controls.

## Working token and component record

### Semantic color and typography tokens

`NekoTheme.kt` is the source of truth. Dark: background `#101416`, surface `#1B2225`, text `#F2F5F4`, muted text `#A7B5B9`, aqua primary `#74E1DD`, primary container `#173B3E`, outline `#455458`. Light: background `#F6F9F7`, white surface, text `#14262B`, muted text `#52676B`, teal primary `#086B70`, mint container `#C4F2ED`, outline `#B1C3C5`. Finance labels and controls use these semantic colors so both modes remain legible.

Typography: large display 38sp, screen title 30sp, section title 24sp, card title 20sp, body 14sp/21sp line height, conversational response 16sp/24sp line height, and small labels 11sp. Allow Android font scaling.

### Spacing and components

- Page inset 24dp; card padding 20dp; common gap 12dp.
- Minimum interactive area 48dp; icon glyphs may be smaller inside that target.
- Card corners 28dp; standard controls 18dp; chat bubbles 22dp; composer 24dp; floating bottom navigation 32dp.
- Conversation message bubbles flex with the screen and cap at 320dp. Native Android's viewport occupies 218dp on home. The web preview's still mascot stage is 208px high and the image remains contained without cropping.
- The greeting and thread scroll above the fixed composer. Transaction rows stay on the ledger destination.

### Motion and accessibility

Native Android's GLB greets with a small paw wave and gentle head motion unless reduced motion is enabled or Neko is paused. In the browser preview, the still cat uses only a subtle idle lift and a short speaking bounce; the reply appears in a comic-tail bubble with an animated typing indicator. The conversation shows a short thinking state while an agent task is queued. Add a descriptive TalkBack label to the native character and useful alt text to the browser image.

Reusable UI reads semantic colors and shared dimensions from the native theme/token layer. Updating a token should update every consumer; subsequent screens should not invent replacements.
