# Neko bug hunt — 2026-10-03

No production code was changed. Regression tests were added only. Findings below are backed by an executed failing test or by the cited source line and an exact repro input. Items that need a device, real bank sample, or another unavailable environment are listed as unverified.

The Android network boundary was reviewed at `Network.request` and its callers. Automatic transaction sync builds a whitelist of transaction fields and excludes SMS body, references, and notes (`AgentRepository.kt:33-58`); pairing, login, chat, and Splitwise use separate payloads. The capture path does send the transaction ID, which is derived from a normalized SMS body in some cases; possible inference from that digest remains unverified below.

## Unverified suspicions

- **UPI result may settle the wrong pending item.** `NekoApp.kt:50-53` receives a result without a transaction ID; `NekoViewModel.kt:136` selects `currentPendingUpi()`, which returns the most recently pending ID. A late result for an older payment could settle a newer one. I could not exercise overlapping external UPI activities on a device.
- **SMS-derived fingerprints leave the device as transaction IDs.** When SMS has no account/reference, `SmsParser.kt:42-43` hashes the normalized full body. `AgentRepository.sync()` sends `t.id`. The raw body is not in the ordinary sync payload, but a stable digest may be guessable for predictable bank templates and amounts. No capture test or protocol trace was available to establish exploitability.
- **Future SQLite upgrades can crash.** `NekoDatabase.kt:42` throws from `onUpgrade` for every version change. Current schema is version 1, so there is no present upgrade pair to reproduce.
- **Permission indicators may go stale after revocation.** `NekoApp.kt:23-27` reads SMS permissions into `remember` state and updates it only from the request callback; `MainActivity.onStart()` does not refresh it. Revoking SMS access in Android Settings and returning may leave the UI saying “Listening for bank SMS.” Device verification was unavailable.
- **Notification denial has no in-app status.** `Notifications.show()` silently returns without `POST_NOTIFICATIONS`; the permission callback does not retain that result. I could not verify what feedback the user sees across Android versions.
- **Other open forms also use non-saveable `remember` state.** Split/group dialogs and statement import fields may lose title, amount, review step, or PDF password on rotation. The added Compose test covers only `TransactionDialog`.
- **Uneven friend-group splits are not exposed.** The visible flow and Splitwise repository post equal splits only. The reviewed docs establish friend groups and bill splitting but do not establish whether uneven allocation is required for this release.
- **Bank format coverage remains synthetic.** Hindi-only input is confirmed to be dropped by the current parser, but no real regional bank template was available. Footer wording, multiple amount ordering, bank-specific reversals, and transaction duplicate IDs need real, locally supplied samples.

## Resolution — 2026-10-03

All findings C-01 to C-09, H-01 to H-03 and M-01 to M-05 were fixed. Verified: `:core:test` (65 tests, 0 failures, including every new regression), `:app:testDebugUnitTest`, `:app:compileDebugAndroidTestKotlin`, `:app:lintDebug` (0 errors), backend `tsc --noEmit`, and the three isolated backend regression suites (5/5). Gradle runs when `GRADLE_USER_HOME` is outside OneDrive (OneDrive locks the transform cache) and the daemon is started outside the sandbox. Not run: the Compose instrumentation tests (the `Neko_API_36` AVD has no system image, so it cannot boot) and the PostgreSQL route tests in `backend.test.ts` (credentials for the validation branch are still rejected).

Behavior changes to know about:
- **C-05:** a notice without a bank reference now includes the SMS timestamp in its fingerprint. Inbox catch-up reads `DATE_SENT`, the same timestamp the live receiver sees. Phones that store `0` fall back to `DATE`, and on those phones a live capture and a catch-up can produce one extra draft. Notices captured during the hour before this update can be re-read once as a duplicate draft.
- **C-06:** only a shared bank reference merges an SMS with a statement row. A same-amount match on a nearby day is kept as a draft and its note names the possible duplicate. On import, such rows are not bulk-confirmed.
- **H-03:** a statement import marks `account|month` as reconciled. Any month that has counted entries in an account without a statement shows "Coverage incomplete". A statement that covers only part of a month still marks the whole month.
- **C-08:** OTP, PIN, CVV, password, passcode, and card-number text is rejected in the backend (chat and corrections) and before Android stores or sends chat.
